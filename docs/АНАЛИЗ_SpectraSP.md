# Анализ установленной SpectraSP (MS7504i № 20126)

Исходные данные: архив `СпектраСП выгрузка с компа из директории напрямую.rar` —
содержимое `C:\ProgramData\SpectraSP for MS7504i N020126` (SpectraSP 1.1.9.4601,
сборка 18755, 2025 г.) и два журнала работы (11.09 и 25.09.2026).

## Состав установки

| Устройство | Что используется | Адрес / порт (из файлов SpectraSP) |
|---|---|---|
| Монохроматор-спектрограф SOL instruments MS7504i № 20126 | `SSPL_IM.dll` → `DevCtrl.dll` → `SOLCon.DLL` | Ethernet, `192.168.120.120` (`DevCtrl.ini`) |
| ПЗС-камера PSI (ProScan Special Instruments), ID 160082, 2048×506, пиксель 12 мкм, охлаждение до −50 °C | `psi_ccd2_ver0.dll` → `psi_ccd5.dll` | Ethernet, `192.168.240.181`, MAC `00-1B-EB-44-E0-28` (`Sensor_160082.xml`) |

Монохроматор: турель с 4 решётками (1800, 600, 1800, 600 штр/мм), входная и
боковая выходная щели, выходное зеркало («Top (CCD)» / «Lateral (Slit)»),
шторка. Фокусное расстояние 754 мм (параметры в `MS7504_20126.cfg`).

## Что показали журналы

Журналы `Logs\*.zip` зашифрованы (XOR 0xAA). Расшифровать их можно утилитой
`python -m spectra_better.logsp файл.zip` — получится обычный текст.

### 1. Каждый спектр снимается ~9,7 секунды при экспозиции 1 с

Все 31 спектр в сессии 11.09 (экспозиция 1 с):

| Этап | Время |
|---|---|
| повторная передача всех параметров камеры перед каждым кадром (≈10 сетевых запросов) | ≈1,1 с |
| экспозиция + **считывание полного кадра 2048×506** (1 036 288 пикселей при 250 кГц) | 5,25 с |
| передача кадра по сети (2 МБ) | 1,4 с |
| обработка в SpectraSP (сумма строк полосы и т. п.) | ≈0,7 с |
| служебные паузы | ≈1,3 с |
| **итого на один спектр** | **≈9,7 с** |

При экспозиции 100 мс спектр всё равно занимает 8,2 с. Полезная доля времени —
около 10 %. Причина: SpectraSP читает с матрицы весь кадр, а спектр строит
программно, суммируя строки полосы (в `ImgWndConfig.cfg` — строки 282…311).
Камера же умеет объединять строки аппаратно (`wMaxVBinning = 506`): тогда
считывается одна строка из 2048 пикселей (~10 мс вместо 4 с).

### 2. Интерфейс «замирает»

Экспозиция (`psiccd2_StartWaitMeasure`) выполняется в главном потоке SpectraSP
через конечный автомат на таймере — на 5–10 с окно перестаёт реагировать; то же
при движении монохроматора (функции SSPL_IM внутри ждут окончания предыдущего
движения). Прервать долгую экспозицию нельзя.

### 3. Долгий запуск и лишние опросы

При запуске SpectraSP последовательно пытается открыть все включённые типы
камер (`UsedSensors` в `SpectraSP.xml`):

* `Sensor_PSI_CCD_VER5_IR` с адресом `192.168.242.181` — такого устройства нет,
  3 с ожидания ping;
* `Sensor_ANDOR` — камера не подключена, 1,2 с на загрузку драйвера Andor.

Инициализация монохроматора (`ctrl_Init`) занимала 4 с, а 25.09 — 36 с
(вероятно, с выводом механизмов в исходное положение после включения).

### 4. Прочее

* Охлаждение ПЗС работало на уставке **+4 °C** (минимум камеры −50 °C). Для
  экспозиций ≥1 с темновой ток при +4 °C заметен; если камера рассчитана на
  глубокое охлаждение, имеет смысл работать при −20…−40 °C (решение за
  пользователем; программа только предлагает уставку).
* Калибровка шкалы в SpectraSP — «Static», центральный пиксель 469, параметр
  «ширина пикселя» 8 (физический шаг матрицы 12 мкм). Файл
  `BaseWLClbr_1.wlc` содержит две реперные точки (пиксель 1070 → 1064 нм,
  1832 → 1083 нм), что соответствует решётке 600 штр/мм и дисперсии
  ≈0,025 нм/пикс. Геометрическая модель по параметрам `MS7504_20126.cfg`
  даёт 0,0255 нм/пикс — совпадение в пределах 3 %.
* Длительная смена длины волны (до ~55 с на 150 нм) и решётки — это скорость
  механики прибора, программно не исправляется.
* Ошибок связи в журналах нет: оборудование и драйверы исправны, проблемы — в
  организации работы программы.

## Что исправлено

1. **Новая программа SpectraSP Better** (папка `spectra_better/`), которая
   использует те же драйверы и адреса, но:
   * снимает спектр с аппаратным объединением строк полосы — при экспозиции
     1 с спектр получается примерно за 1,1–1,3 с вместо 9,7 с (оценка по
     скоростям считывания; окончательно проверяется утилитой `probe`);
   * передаёт параметры в камеру только при их изменении;
   * работает с приборами в отдельных потоках: окно не замирает, экспозицию
     можно прервать, «зависшая» камера обнаруживается по таймауту;
   * не опрашивает отсутствующие камеры;
   * подробный текстовый журнал (обычный текст, не зашифрованный).
2. **Утилита `tools/tune_spectrasp.py`** для оригинальной SpectraSP: выключает
   опрос отсутствующих камер (−4 с при каждом запуске) с резервной копией.
   Адреса и порты не трогаются.
3. **Утилита `logsp`** для чтения журналов SpectraSP.
4. **Утилита `probe`** — пошаговая проверка связи с приборами.
